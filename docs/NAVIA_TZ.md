# NAVIA — техническое задание для Codex

**Файл в репозитории:** `docs/NAVIA_TZ.md`
**Связанный документ:** `docs/NAVIA_CONSTITUTION.md` — продуктовая конституция и полный аудит (подробности по GNSS, маршрутизации, офлайну, укрытиям, ИИ, чек-листам).
**Приоритет при противоречиях:** текущий промпт → этот ТЗ → конституция → существующий код.

---

## 0. Принятые решения

Эти решения действуют, пока владелец не изменит их явно.

| Вопрос | Решение |
|---|---|
| Язык интерфейса | Украинский. Все строки — через централизованную локализацию. Русский в интерфейсе NAVIA не допускается. |
| Язык голоса | Украинский по умолчанию (`uk-UA`). Архитектура озвучки должна позволять добавить другой язык позже, но в этой итерации — только украинский. |
| Режим работы | Одна фаза за раз. После фазы — остановка, отчёт и вопросы. Внутри фазы очевидные инженерные решения принимай сам, не спрашивай. |
| Среда | Codex CLI на Mac владельца (нужны Xcode, CocoaPods, симулятор iOS, Metro). Облачная среда без macOS не подходит для фаз со сборкой. |
| Шрифт | Спросить в фазе 0: Inter или системный (SF Pro / Roboto). До ответа — не менять шрифты. |
| Логотип-маркер | Спросить в фазе 0, есть ли SVG логотипа и нужна ли отдельная версия под маркер. |
| Провайдер голоса | Выбирается в фазе 10а по сравнению вариантов. До выбора — не подключать платные API. |

## 1. Цель итерации

NAVIA должна ощущаться как продукт уровня Google Maps, Apple Maps, Waze, а по аккуратности интерфейса — как Uber, Revolut, Airbnb, Telegram: продуманно, спокойно, надёжно.

«Премиально» здесь значит: иерархия, сдержанность, единообразие, точность, отзывчивость, ясные состояния ошибок, сильная типографика, дисциплина отступов, осмысленная анимация. Не значит: градиенты, стекло, неон, лишние карточки и эффекты.

Ориентиры изучать как принципы, не копировать: никаких чужих логотипов, иконок, фирменных элементов и пиксельных копий раскладок.

## 2. Непреложные принципы

1. **Честность.** Функция либо работает по-настоящему, либо честно показано, что она недоступна. Ничего не выдумывать: координаты, дороги, прогресс маршрута, POI, укрытия, состояние GPS, готовность офлайна.
2. **Не ломать работающее:** таймер заставки, построение маршрута, получение GPS, переходы между экранами, всё, что сейчас запускается на устройстве.
3. **Навигационная логика — в движках, не в экранах.** UI только отображает состояние, не вычисляет его.
4. **Высокочастотные данные (IMU, сырые фиксы) не гнать в React.** UI получает дросселированный снимок состояния.
5. **Никакого хардкода** цветов, размеров, отступов, шрифтов, строк — только токены и локализация.
6. **Не выполнять деструктивных действий** без необходимости: полная переустановка зависимостей, `npm audit fix --force`, регенерация нативного проекта, удаление тестов.
7. **Точное местоположение не отправлять** ни в ИИ, ни в сторонние сервисы по умолчанию. Всё, что уходит с устройства, — задокументировать.

## 3. Правила работы

1. Перед правками в каждой фазе: `git status`, сохранить незакоммиченную работу владельца, понять расхождение локальной копии и GitHub.
2. Одна фаза — одна ветка, логичные небольшие коммиты, тесты вместе с изменением поведения.
3. Не угадывать то, что зависит от владельца (бренд, язык, деньги, ключи, данные). Вопросы — нумерованным списком с вариантами ответа и рекомендацией. Пока ждёшь ответ — делай то, что от него не зависит.
4. Инженерные решения, у которых есть очевидный правильный вариант, принимай сам и указывай в отчёте.
5. Сначала воспроизвести проблему или найти достоверную причину, потом чинить. Не менять десять вещей одновременно.

## 4. Проверка и статусы

### Проверка перед отчётом (обязательно)

- Зависимости: нет дублей React Native и `react-native-safe-area-context`, нет новых конфликтов (`npm ls`, Expo Doctor).
- TypeScript, lint, unit-тесты — без новых ошибок и предупреждений. Приложить команды и вывод.
- Сборка iOS и запуск в симуляторе, проход по всем изменённым экранам.
- Старая функциональность: заставка по таймеру, построение маршрута, GPS, переходы.
- Анимации: 200–400 мс для элементов UI (переходы камеры — до 1,5 с), плавный easing, цель 60 fps, анимировать transform/opacity.
- Маленький и большой iPhone, светлая и тёмная тема (если тёмная есть), длинные украинские строки.
- Скриншоты изменённых экранов, если среда позволяет.

### Статусы (использовать строго)

- **IMPLEMENTED** — код есть.
- **AUTOMATED-TESTED** — автотест прошёл.
- **RUNTIME-TESTED** — проверено в запущенном приложении (симулятор).
- **DEVICE-VERIFIED** — проверено на физическом iPhone (только при реальных доказательствах).
- **PARTIAL** — работает частично, требование не выполнено.
- **BLOCKED** — нужен ключ, аккаунт, действие владельца.
- **NOT IMPLEMENTED** — отсутствует.

Слово «готово» не использовать. Если на устройстве не проверено — статус не выше RUNTIME-TESTED, и перечислить, что должен проверить владелец на телефоне.

### Формат отчёта после каждой фазы

1. Что сделано (по пунктам, со статусами).
2. Изменённые файлы.
3. Что проверено и как (команды, вывод, скриншоты).
4. Что не проверено и почему.
5. Что нужно от владельца (ключи, файлы, действия на телефоне, решения).
6. Вопросы — нумерованные, с вариантами и рекомендацией.

## 5. Дизайн-система (требования для всех фаз после фазы 2)

- **Цвета — семантические токены:** background, surface, surfaceElevated, border, divider, textPrimary, textSecondary, textMuted, accent, success (GPS надёжен), warning (GPS нестабилен), critical (GPS потерян), routeLine, routeCasing, routeTraveled, mapHalo, pressed, disabled. Светлая и тёмная палитра.
- **Отступы — только сетка:** 4, 8, 12, 16, 24, 32, 48. Горизонтальный отступ экрана — 16.
- **Типографика — один шрифт,** уровни с фиксированными размером, насыщенностью, межстрочным интервалом (подходящим для кириллицы): display, maneuver (крупный, для навигации), screenTitle, sectionTitle, body, bodySecondary, caption, button, chip, numeric (табличные цифры).
- **Радиусы:** small / medium / large / pill — одни на всё приложение.
- **Тени/возвышение:** 2–3 уровня, одинаково на iOS и Android.
- **Линии:** одна толщина и один цвет разделителей, строго по сетке.
- **Иконки:** один стиль (обводка/заливка), размеры 16 / 20 / 24 / 32.
- **Касание:** минимум 44×44 pt.
- **Анимация:** fast 200, normal 300, slow 400 мс; кривые easing в токенах; уважать «уменьшение движения».
- **Базовые компоненты:** Text, Button, IconButton, Chip, Card, Divider, ListRow, BottomSheet — только на токенах.

## 6. Фазы работ

Фазы выполняются строго по порядку. Следующая — только после отчёта по предыдущей и ответа владельца.

### Фаза 0. Аудит без изменений кода

- Стек и версии, реально установленные (не из `main` на GitHub): `git status`, `git diff`, `package.json`, lockfile, `npm ls`, `Podfile.lock`, Expo Doctor.
- Структура папок, дерево навигации, список всех экранов (назначение, вход, выход).
- Где стили, темы, шрифты; сколько хардкода.
- Картографический SDK, камера, маршрут, маркер пользователя.
- GPS/GNSS: библиотека, частота, индикатор, есть ли гистерезис.
- Движки из конституции (раздел 4): какие есть, какие нет, где логика живёт в экранах.
- Маршрутизация: провайдер, демо-режим, откуда берутся маршруты.
- Озвучка: библиотека, язык, где формируются фразы.
- Заставка и её таймер.
- Тесты, lint, typecheck — команды и текущий результат.
- Эмуляция движения по маршруту — есть ли.
- Список строк не на украинском.
- Воспроизвести и описать известные проблемы: запуск/крэш, зум карты, компас под карточкой манёвра, кривые маршруты, мигающий индикатор GPS, лаги.
- Итог: карта рисков по приоритету и вопросы владельцу (шрифт, логотип, всё неясное).

### Фаза 1. Стабильный запуск

- Детерминированный старт на полном дереве навигации, без зависания на заставке.
- Устранить дубли нативных модулей и несовместимые версии осознанно, без слепой переустановки.
- Если причина не очевидна — бинарная изоляция: минимальный App → NavigationContainer → стек → экраны по одному → провайдеры по одному.
- Каждый найденный крэш: шаги воспроизведения, стек, причина, исправление, регрессионный тест.

### Фаза 2. Дизайн-система и локализация

- Модуль токенов и базовые компоненты по разделу 5.
- Централизованная локализация, все строки NAVIA — на украинском. Русский и случайный английский — убрать (английский допустим только в диагностике для разработчика).
- Перевести все экраны на токены и компоненты (по экрану за коммит). Логику не менять.
- В конце — поиск оставшегося хардкода (hex, rgb, числовые размеры/отступы, строки в JSX) и список с объяснением, почему оставлено.

### Фаза 3. Заставка

- Логику и таймер показа не трогать (показать в диффе).
- Убрать точки-разделители между мотивационными фразами; каждая фраза — отдельной строкой, столбиком, по центру; одинаковый интервал; шрифт из токенов.
- Анимация: строки появляются по очереди — fade-in + сдвиг снизу вверх на 8–12 pt, 300 мс на строку, задержка 120 мс между строками, ease-out. Анимация не задерживает закрытие.

### Фаза 4. Карта: жесты, камера, раскладка

Блокеры релиза из конституции (разделы 30, 55, 56).

- Pinch-zoom, кнопки +/−, панорама, поворот, сброс компаса, recenter — работают на самом деле.
- Камера не перезаписывает зум/позицию пользователя при каждом обновлении состояния.
- Режим следования: жест пользователя выключает его, recenter возвращает.
- Раскладка по зонам, а не по случайным абсолютным отступам: верхняя зона (карточка манёвра + индикатор GPS), правая колонка управления (компас, recenter, зум), нижняя панель. Компас никогда не перекрывается карточкой манёвра при любой её высоте, длинных названиях улиц, баннерах и любой ширине iPhone.
- Оверлеи не перехватывают жесты карты.

### Фаза 5. Индикатор GPS и главный экран

**Индикатор GPS** показывает надёжность позиции, а не частоту обновлений и не «силу сигнала» (iOS её не отдаёт — полоски сигнала не выдумывать).

- Три состояния по данным движков (свежесть фикса, точность, аномалии, согласованность с дорогой/маршрутом, уверенность):
  - зелёный — `GPS стабільний`;
  - жёлтый — `GPS нестабільний`;
  - красный — `GPS втрачено` / `Оцінюю положення за датчиками` / `Положення невпевнене`.
- Компактный чип: иконка + короткий текст. Цвет — не единственный сигнал: иконка различается по состоянию.
- Гистерезис: разные пороги входа и выхода, минимальное время в состоянии. Никакого мигания на каждом фиксе. Юнит-тесты на последовательности сэмплов.
- Смена состояния анимирована: cross-fade текста 200–250 мс, плавная смена цвета, ширина чипа без рывков.
- Тап по чипу — короткое пояснение состояния.
- Dev-переключатель состояний (только в dev-сборке) для проверки всех трёх.

**Главный экран:**

- Отвечает на вопрос «что я могу сделать?». Главное действие — `Куди їдемо?`.
- Далее: недавние направления (с пустым состоянием), `Знайти укриття`, ИИ-навигатор, статус офлайн-карт, настройки. Диагностика — только в dev-сборке.
- Единое выравнивание, одинаковые отступы между блоками (24) и внутри (12–16). Перед изменением — предложить структуру блоков списком.
- Pull-to-refresh: запрашивает свежий фикс; индикатор плавно появляется и исчезает; состояние GPS меняется только по реальным данным.

### Фаза 6. Корректность маршрута

Блокер релиза (раздел 57). Не украшать неправильный маршрут.

- Пройти цепочку: ввод адреса → геокодинг → точка старта → запрос → провайдер → ответ → геометрия → манёвры → прогресс → уход с маршрута → перестроение → прибытие.
- Проверить порядок lat/lon, декодирование геометрии, единицы, расстояния манёвров, ETA, названия улиц.
- Проверки здравого смысла ответа (маршрут начинается у пользователя, заканчивается у цели, длина правдоподобна). HTTP 200 — не доказательство.
- Демо-маршрут никогда не выдаётся за реальный; демо-режим явно помечен.
- Ошибки и таймауты провайдера — честное состояние с возможностью повторить.
- Уход с маршрута и перестроение с гистерезисом, без бесконечных циклов.
- Эмуляция движения по построенному маршруту (dev), подающая данные в те же движки, что и реальный GPS, — нужна для фаз 7–9.

### Фаза 7. Старт маршрута и режим навигации

Эталон — кнопка «В путь» в Google Maps. Кнопка у нас: `Почати` (или предложить вариант).

- Явное состояние режима: обзор маршрута → навигация → завершение → обзор.
- По нажатию — анимация камеры 1–1,5 с: приближение к текущей позиции (zoom ~17–18), наклон 45–60°, поворот по курсу (если курса нет — по направлению первого сегмента).
- Интерфейс перестраивается плавно: элементы обзора уходят (fade + сдвиг, 250–300 мс), навигационные панели появляются.
- Камера следует за пользователем и вращается по курсу; позиция пользователя — в нижней трети экрана.
- **Сверху** — карточка манёвра: крупная стрелка, расстояние (`300 м`, `1,2 км`), название улицы; ниже мелко — следующий манёвр (`Потім ліворуч`). Смена манёвра анимирована.
- **Снизу** — одна панель: время прибытия, оставшиеся время и километры, кнопка завершения.
- Жест по карте — следование выключается, появляется кнопка `Повернутися до маршруту`, по нажатию камера плавно возвращается.
- Прибытие — явное состояние с названием места и кнопкой завершения; никаких «поверніть через 0 м».
- Завершение — плавный обратный переход к обзору.
- Форматирование расстояний и времени — отдельные функции с юнит-тестами (украинские формы числительных).
- Safe area на всех iPhone.

### Фаза 8. Маркер местоположения — логотип NAVIA

- Вместо стандартной стрелки — логотип NAVIA (файл от владельца; если нет — BLOCKED и вопрос).
- Поворачивается по курсу; на малой скорости держит последний курс, не дёргается.
- Плавное перемещение: интерполяция позиции и угла между фиксами (угол — по кратчайшей дуге).
- Под логотипом — мягкий полупрозрачный круг точности/уверенности и лёгкая пульсация.
- Виден на светлой и тёмной карте (белая обводка и/или тень).
- Точно центрирован на координате, постоянный оптический размер при зуме, корректно реагирует на поворот карты.
- При деградации GPS визуально отражает меньшую уверенность, не вводя в заблуждение.
- Нативный слой SDK, без просадки fps.

### Фаза 9. Подсказки манёвров и оформление маршрута

Эталон — Waze и Google Maps.

- Набор векторных иконок манёвров в одном стиле: прямо, плавно/резко ліворуч/праворуч, розворот, круговий рух с номером з'їзду, з'їзд, злиття, прибуття. Полосы движения — только если провайдер отдаёт данные (проверить и сообщить).
- Карточка манёвра читается за одну секунду: крупная стрелка, крупное расстояние, минимум текста, высокий контраст.
- Линия маршрута: насыщенный цвет, лёгкая обводка, пройденная часть приглушена или скрыта; ширина адаптируется к зуму; маршрут выше дорог, но не перекрывает важные POI.
- Спокойная гамма, ничего не бьёт по глазам.
- Ночной режим карты и панелей (переключение — по системной теме, если владелец не решит иначе).
- Скриншоты: прямо, поворот, круговое движение, ночь, GPS жёлтый, GPS красный.

### Фаза 10а. Голос — сравнение вариантов (без кода)

- Сравнить 3–4 варианта нейросетевого TTS с качественным украинским (например: OpenAI TTS, ElevenLabs, Google Cloud TTS, Azure Neural TTS): качество украинского, мужской и женский голос, задержка, цена за типовой маршрут, офлайн-возможности.
- Ключ API — не в клиенте. Предложить схему (свой прокси/бэкенд).
- Что уходит с устройства (текст фраз с названиями улиц) — описать для раздела приватности.
- Архитектура: генерация фраз, кеш, резервный системный TTS, приглушение музыки.
- В конце — вопросы для выбора.

### Фаза 10б. Голос — реализация

- Сервис озвучки с одним интерфейсом и провайдерами: нейросетевой + системный `uk-UA` как резерв.
- Женский и мужской голос; в настройках выбор с кнопкой прослушивания; выбор сохраняется.
- Естественные фразы с правильными формами: «Через 300 метрів поверніть праворуч на вулицю Шевченка», «На круговому русі другий з'їзд», «Ви прибули». Юнит-тесты на формирование фраз.
- Кеш: частые фразы заранее + кеш на устройстве; без заметной задержки.
- Нет сети, ошибка или таймаут провайдера — автоматически системный TTS.
- Приглушение музыки на время фразы (audio ducking), не остановка. iOS и Android.
- Без наложения фраз, без повторов одного манёвра, корректный mute.

### Фаза 11. Производительность

- Профилировать, а не гадать: частота ререндеров, подписки Zustand, пересоздание объектов и геометрии, поток IMU 10 Гц, таймеры, повторные запросы, логи.
- Замерить до и после.
- Высокочастотные данные — вне React; UI получает дросселированный снимок.
- Не снижать точность навигации ради скрытия лагов.

### Фаза 12. Укрытия, POI, ИИ — честная интеграция

По разделам 15–18 конституции:

- Укрытия: источник данных указан, маркер отличим, «безопасно» не утверждается, пустое состояние `Немає доступних даних про укриття для цієї області.`, маршрут через обычный движок.
- ИИ отвечает только по данным движков; если данных нет — говорит, что не может подтвердить. Точное местоположение не отправляется по умолчанию.
- Микрофон без распознавания речи не выглядит рабочим — честное состояние «недоступно».

### Фаза 13. Полный регресс и финальный отчёт

- Финальный отчёт в формате раздела 66 конституции со статусами из раздела 4 этого ТЗ.

## 6а. Итерация 2 — запросы владельца (24.09.2026)

Решения владельца: шрифт — системный SF Pro; английский язык остаётся (через локализацию); слои — MapTiler; вход — Firebase; заставка ~2 с (первый запуск дольше); угрозы — только тревога и сводка по области.

Дополнительно: тема — как в системе iPhone (карта в навигации темнеет ночью); платформа — только iPhone (код совместим с Android); кнопка «Найближче укриття» при активной тревоге (пеший маршрут к ближайшему известному укрытию, без слова «безпечне»); поиск как в Google Maps (экран поиска с недавними → карточка места → «Маршрут»); сохранённые места «Дім», «Робота» и свои; настоящий ИИ-штурман на Claude (Anthropic) через Firebase Functions, ключ только на сервере, ответы только по данным движков; офлайн-карты — после дизайна и навигации. Apple Developer владелец оформит (до этого вход через Apple — BLOCKED); режимы маршрута — авто и пешком (выбор в карточке маршрута); push-уведомлений о тревогах пока нет; слоган «Навігуй · Дій · Будь у безпеці» — только в заставке, на главном экране его нет. ИИ-штурман: текстовый чат в панели + голос (микрофон, ответ голосом) во время езды; ИИ не получает координаты — только улицу, район, маршрут, статус GPS и места рядом. Вход необязателен: всё основное работает без него; вход нужен для синхронизации и ИИ-штурмана. Бюджет платных сервисов на тестах — до $20/мес, на сервере лимиты запросов.

Порядок: фаза 1 (снимок-коммит, стабилизация) → фаза 2 (дизайн-система, локализация) → **2.1 главный экран** → **2.2 слои карты** → **2.3 заставка и обучение** → фазы 5–10 → **2.4 вход**.

### 2.1 Главный экран в стиле Google Maps (в цветах NAVIA)
- Карта на весь экран, моё местоположение — логотип NAVIA (фаза 8 частично переносится сюда).
- Сверху — строка поиска: ввод адреса сразу, без перехода на отдельный экран-заглушку; кнопка профиля/настроек в строке.
- Под строкой — горизонтальные чипы категорий: Укриття, Пункти незламності, АЗС, Зарядки, Аптеки, Лікарні, Банкомати, Вода. Нажатие показывает точки на карте и список в нижней панели.
- Снизу — выдвижная панель (3 положения: свернута / половина / почти весь экран). В ней: состояние GPS (зелёный/жёлтый/красный по надёжности), тревога в моём районе, сводка по области («в області повідомляють про БпЛА», источник и время), вход в ИИ-штурмана.
- Кнопки карты справа: слои, моё местоположение, компас (по необходимости).
- Мелкий текст об источниках и оговорки — убрать с экрана, собрать в один экран «ⓘ Джерела даних». Подпись «© OpenStreetMap» на карте оставить (требование лицензии).
- ~~Точки воздушных целей на карте НЕ показывать.~~ Изменено владельцем 29.09.2026 (ТЗ «Карта цілей»): цели показываются в отдельном режиме «Цілі» из нижней панели — только из легального открытого API (NEPTUN), с названием источника и ссылкой, временем обновления и постоянным предупреждением, что это орієнтовні дані спільнотного моніторингу, не офіційна інформація; при недоступности источника — «дані тимчасово недоступні», не пустая карта.
- Pull-to-refresh заменяется обновлением по кнопке/жесту в панели; смена статусов анимирована.

### 2.2 Слои карты
- Кнопка слоёв → лист выбора: Стандартна / Супутник / Рельєф; переключатель 3D-будівель, если стиль поддерживает.
- Источник — MapTiler (ключ `EXPO_PUBLIC_NAVIA_MAPTILER_KEY`, владелец кладёт его в `apps/mobile/.env`). Без ключа — слои Супутник/Рельєф показаны как недоступные, а не пропадают молча.
- Выбор слоя сохраняется; ночной режим для стандартной карты.

### 2.3 Заставка и обучение
- Своя анимация логотипа NAVIA с «вау»-эффектом (не копия Netflix): ~2 с при каждом запуске, при первом — полная версия; звук `navia-intro.wav` по настройке. Плавный переход в карту без белой вспышки; нативный splash совпадает с первым кадром анимации (стрелка логотипа направлена вверх).
- Обучение при первом запуске: 3–4 экрана (карта и поиск, GPS-индикатор, укрытия и тревоги, ИИ-штурман), можно пропустить; запрос геолокации — с объяснением на экране обучения.
- Обновление по запросу владельца (30.09.2026): заставка «кинематографичная, космос, вау, как Netflix» — прыжок сквозь звёзды, туманность, край планеты, эмблема и буквы, влёт в эмблему через цветные световые ленты с вибрацией; первый запуск ≈3,8 с, далее ≈2,3 с; при «Уменьшении движения» — спокойная версия (`IntroOverlay.tsx`). Обучение — 7 страниц на одной сетке (сцена и текст фиксированного размера и места), отдельный шаг «Штурман NAVIA» с живой сценой диалога (`Onboarding.tsx`, `StoryScenes.tsx`).

### 2.4 Вход в аккаунт
- В настройках: вход через Apple, Google, почту (Firebase Auth). Что синхронизируется: избранное, история маршрутов, настройки.
- Владелец создаёт проект Firebase и добавляет `GoogleService-Info.plist`; для входа через Apple нужен платный Apple Developer. Без этого — статус BLOCKED, UI входа не показывается как рабочий.
