## 1. Цель продукта и конечный результат

**NAVIA — навигатор с живым голосовым штурманом, который доводит водителя до цели, даже когда
GPS пропал, заглушён или врёт (тревога, РЭБ, тоннель, паркинг), и даже без интернета.**

Конечный результат версии 1 глазами водителя (Киев и область, iPhone в держателе):

1. Водитель говорит «Навиа, веди на Васильковскую» — маршрут строится, голос ведёт по поворотам.
2. Во время тревоги GPS начинает прыгать. NAVIA **сама замечает**, что сигнал подозрительный,
   не прыгает вслед за ложной точкой и говорит: «GPS ненадёжен, веду по датчикам телефона».
3. GPS пропал совсем. Навигация **не останавливается**: позиция считается по гироскопу,
   акселерометру и карте. Пока уверенность высокая, подсказки идут как обычно; когда она падает,
   подсказки становятся приблизительными («примерно через 300 м»).
4. Когда неопределённость большая, **штурман сам просит помощи**: «Скажи, что видишь вокруг».
   Водитель описывает словами («Фора, за ней перекрёсток», «метро, напротив Дніпро-М»). Штурман
   **ищет эти объекты на реальной карте** в районе, где машина может быть. Он проверяет, что
   совпадение единственное, **переставляет позицию** навигатора туда и ведёт дальше от ориентиров.
5. Когда GPS возвращается и снова надёжен, позиция плавно (без скачков экрана) переходит на GPS.
6. В любой момент можно спросить по-человечески: «где заправиться до 5 минут крюка», «вторая норм,
   добавляй», «сколько ещё», «почему так едем», «напомни про кофе через полчаса». Штурман
   понимает, считает через инструменты, спрашивает подтверждение на серьёзные изменения и
   **никогда не выдумывает** места, расстояния и позицию.
7. Без интернета маршрут, ведение и навигация без GPS работают на сохранённых данных. Умные ответы
   честно сообщают, что нужна сеть, а базовые ответы работают локально.

Критерий «готово» для v1 — раздел 7 («Приёмка»). Пока все пункты не доказаны, продукт не готов.

## 2. Честное текущее состояние

### 2.1 Что есть в коде и доказано автоматически

| Область | Что есть | Доказательство |
|---|---|---|
| Навигация без GPS | `ResilientNavigator`: фильтр частиц по дорожному графу, гироскоп и акселерометр, проверка GPS на правдоподобие, противодействие подмене, восстановление | 100 000 симуляций замкнутого цикла: доехал **90,5 %** против 67,9 % у базовой версии; «уверенно не там» **5,1 %** против 57,4 % (`packages/core/sim/reports/mc-100k.json`, `docs/GNSS_DENIED_REPORT.md`) |
| Состояния позиции | `LocationStateTracker`: PRECISE / REDUCED / STALE / UNSTABLE / LOST / SPOOFED / RECOVERED; подсказки exact / approximate / none | 18 сценариев в `test/location-resilience.test.ts`: 5 с / 30 с / 2 мин потери, тоннель, паркинг, дрейф, прыжок, восстановление |
| Штурман (агент) | Цикл «LLM ↔ инструменты», 20 инструментов, политика read / safe / confirm, планы из нескольких действий, память, напоминания, предпочтения, проактивность, голос «Навиа…» | 212/212 тестов; eval: dev 265, holdout 59 |
| Серверная прослойка | `apps/ai-backend`: ключ только на сервере, Anthropic или OpenAI-совместимый провайдер | тесты бэкенда |
| Офлайн | Нет интернета ≠ нет GPS; активная поездка сохраняется в кэш; маршрут сохраняется при неудачном перестроении | тесты + `NavigationScreen.tsx` |

### 2.2 Что НЕ проверено ни разу (главные риски)

1. **Живой LLM не подключался ни разу.** В облачной среде нет `ANTHROPIC_API_KEY`. Результат
   holdout 58/59 получен в режиме «модель-в-цикле», где решения принимал Claude в сессии
   разработки, а не живой вызов API из приложения.
2. **Приложение ни разу не собиралось в Xcode и не запускалось на iPhone.** Проверен только
   JS-бандл (`expo export`).
3. **Ни одной реальной поездки.** 90,5 % — это симуляция на синтетических городах, а не Киев.
4. Нет `apps/mobile/assets` (иконки), поэтому prebuild не пройдёт без них.

### 2.3 Почему штурман «работает как шаблон и не думает» — точные причины

Ощущение правильное, но причина не в том, что «AI не способен думать». Причин четыре, и все
проверяемы:

| # | Причина | Где в коде | Следствие |
|---|---|---|---|
| 1 | **Мозг не подключён.** Без ключа на бэкенде, без URL бэкенда в приложении или без согласия приложение уходит в `DeterministicDemoAIProvider`: 4 regex-корзины и шаблонные фразы | `packages/core/src/ai-engine.ts`, префикс «Розумний режим штурмана зараз недоступний» | Скриншоты с «плохими ответами» — это именно этот запасной режим |
| 2 | **Нет «рук» для главного сценария.** Нет инструмента «найди, где я, по описанию» и нет API, чтобы переставить позицию навигатора по подтверждённому ориентиру | `check_landmark` ищет только **впереди по маршруту**, в окне −100…+1500 м от *оценки* позиции (`tool-executor.ts:593`); у `ResilientNavigator.relocalize` нет публичного входа | Даже умный LLM не может выполнить сценарий «вижу метро и Дніпро-М» |
| 3 | **Нет «глаз» — данных карты.** Категории OSM (`OSM_CATEGORY_SELECTORS`, `place-search.ts`) не включают станции и входы метро, остановки, светофоры, дорожные знаки, строительные и прочие магазины (Дніпро-М = `shop=doityourself`), банки и т. п. В приложении дорожный граф строится **только из линии маршрута** (`networkForRoute` не передан) | `place-search.ts`, `navigation-engine.ts:201` | Штурман не видит 80 % того, что видит водитель |
| 4 | **Не проверено в реальности.** Нет сборки, поездки или живого eval | — | Неизвестно, как это ведёт себя в машине |

Вывод: сначала подключить мозг (п. 1), затем дать ему глаза и руки (п. 2–3), затем доказать
в реальности (п. 4). Дописывать фразы и шаблоны бессмысленно и запрещено (раздел 8).

## 3. Архитектура: кто за что отвечает (не нарушать)

```
Водитель (голос/текст)
   │
   ▼
Штурман = LLM (понимает, рассуждает, выбирает инструменты, ведёт диалог)
   │   видит только компактный <trip_state> и результаты инструментов; координат не видит
   ▼
Инструменты (факты и действия; каждое число считает код)
   │
   ▼
Навигационный движок (позиция, неопределённость, маршрут, манёвры, перестроение) — детерминирован
   │
   ▼
Данные (OSM POI/дороги, Valhalla, датчики iPhone, GPS, тревоги)
```

| Слой | Отвечает за | Никогда не делает |
|---|---|---|
| LLM | смысл любой фразы (рус/укр/англ, суржик, опечатки, «хз какая»), ссылки («вторая», «она»), план из нескольких шагов, выбор инструмента, когда переспросить, короткий ответ голосом | не считает расстояния, не придумывает места и координаты, не решает, где машина |
| Инструменты | поиск по реальным данным, расчёт времени и крюка, уникальность совпадения, действия с подтверждением | не формулируют ответ водителю |
| Движок | где машина и с какой уверенностью (σ, метры), следующий манёвр, перестроение, переход на GPS или ориентир | не разговаривает |
| Приложение | голос, экран, согласие, хранение | не принимает навигационных решений |

**Золотое правило:** штурман думает, движок считает, данные подтверждают. Если данных нет,
штурман говорит «не знаю / нет данных» и предлагает, что можно сделать.

## 5. ШТУРМАН — что он должен уметь и как справляться

### 5.1 Характер

Спокойный опытный штурман рядом с водителем:
- говорит коротко: 1–2 фразы за рулём, до 3 вариантов в движении и до 5 на стоянке;
- ведёт и успокаивает («не переживай, разберёмся»), но **не врёт ради спокойствия**;
- сам спрашивает то, что ему нужно («что видишь справа?»), и не заставляет водителя
  формулировать правильно;
- знает, что у водителя заняты руки и глаза: спрашивает то, что видно без поиска и что легко
  сказать;
- говорит на языке водителя, понимает суржик, сленг, опечатки распознавания, «хз какая»;
- помнит, о чём говорили, и понимает «её», «вторую», «туда», «как в прошлый раз».

### 5.2 Как он думает — цикл каждого хода

1. **Воспринять:** `<trip_state>` (позиция и её качество, маршрут, манёвр, интернет, память,
   фаза вождения) плюс фраза водителя или событие (GPS пропал, напоминание, пробка).
2. **Понять цель:** что водителю нужно на самом деле. Например, «пропал навигатор» = «помоги не
   потеряться и доехать», а не «расскажи статус GNSS».
3. **Решить, каких фактов не хватает,** и вызвать инструменты. Чтения идут параллельно,
   действия последовательно.
4. **Проверить факты:** совпадение единственное? уверенность позволяет давать метры? есть ли
   данные вообще?
5. **Действовать по политике:** чтение сразу; безопасное действие сразу, с возможностью отмены;
   серьёзное действие только с подтверждением.
6. **Ответить коротко** и, если нужно, задать **один** вопрос, который лучше всего разделяет
   варианты.
7. **Запомнить:** результаты, фокус, действия, предпочтения. Следующий ход опирается на это.

Это не набор сценариев. Это один общий цикл. «Миллионы сценариев» закрываются тремя вещами:
- **общие инструменты** — умеют искать любые объекты карты по описанию;
- **реальные данные** вокруг машины;
- **LLM**, который сам комбинирует их под любую фразу.

Ни одна фраза водителя не должна появляться в коде как `if`.

| C8 | Честная неопределённость | «где я?» при σ = 400 м → «примерно на Х, точнее не скажу» | `positioning` в trip_state | ✅ |
| **C9** | **Локализация по описанию водителя при потере GPS** | «вижу Фору и перекрёсток» | **нужен `locate_by_description` + `confirm_position`** | ❌ |
| **C10** | **Ведение от ориентиров, а не от метров** | «за ним направо, ещё ~100 м до перекрёстка» | **нужен `get_guidance_from_here`** | 🟡 (`get_landmarks_ahead` только по маршруту) |
| **C11** | **Ведение по датчикам со слов водителя** | «еду 40», «стою в пробке», «повернул направо» | **нужен `report_driver_observation`** | ❌ |
| **C12** | **Описание места прибытия** | «сразу на остановке — место прибытия» | **нужен контекст финала маршрута** | ❌ |
| C13 | Тревога | «тревога?», «что с GPS?» | `air-alert-layer` | 🟡 🔑 |
| C14 | Без интернета | «интернета нет, что работает?» | локальный запасной режим | ✅ (базовый) |
| C15 | Неизвестная просьба | «какая цена на А-95?» | — | ✅ честно «нет данных о ценах» |

### 5.4 Эталонный сценарий владельца — разбор по репликам

Сценарий ниже — **эталон поведения, а не скрипт**. Для каждой реплики указано, что штурман
обязан сделать внутри, что вправе сказать и что запрещено. Названия и объекты в тестах
берутся **только из реальных данных OSM** (раздел 7). В этом документе они для иллюстрации.

**Реплика 1.** Водитель: «Пропал навигатор, что делать?»
- Внутри: читает `positioning` (например `location_state=LOST`, σ = 350 м, 40 с без фикса,
  `source=DR`).
- Понимает цель: не «объяснить GNSS», а удержать водителя на маршруте.
- Говорит: «Не переживай, GPS пропал, но я веду по датчикам. Скажи, что видишь перед собой
  или рядом?»
- Запрещено: «Вы на ул. Х, через 300 м направо», если σ > 150 м. Запрещены лекции про спутники.

**Реплика 2.** Водитель: «Вижу Фору, а за ней перекрёсток».
- Внутри: `locate_by_description` с объектами `[{supermarket, name_variants:["Фора","Fora"]},
  {junction, relation:"after", of:0}]` в **области неопределённости** движка (вокруг оценки,
  радиус ≈ 3σ, а не только впереди по маршруту).
- Код находит все «Форы» в области, у каждой проверяет перекрёсток в направлении движения,
  считает оценку и **уникальность**.
- Если кандидат один и он на маршруте или рядом: `confirm_position(candidate)` → движок
  переставляет позицию в точку у Форы с σ ≈ 30–60 м. Затем `get_guidance_from_here`:
  следующий манёвр **относительно ориентира**.
- Говорит (только если так в данных): «Отлично, нашёл тебя. На перекрёстке за Форой направо,
  потом ещё примерно 100 м до следующего перекрёстка».
- Про «знак ограничения скорости слева» — **только если** в OSM есть этот знак
  (`traffic_sign` / `maxspeed` на узле). Иначе описывает то, что есть в данных (светофор, АЗС,
  остановку) или ничего.
- Если Фор две: **один различающий вопрос**, который код посчитал как лучший разделитель
  («Фора слева или справа?» / «рядом есть заправка?»).
- Если ни одной: «Фору рядом не нахожу. Что ещё видишь — вывеску, остановку, название улицы?»
  Позицию не трогать.

**Реплика 3.** Водитель: «Супер, я тут, куда дальше?»
- Внутри: водитель подтвердил, что он у ориентира. Это ещё одно наблюдение, σ сужается.
  Затем `get_guidance_from_here`.
- Говорит маршрут дальше, из данных. Если уверенность после привязки позволяет, продолжает
  обычное ведение.
- Говорит о режиме **честно, а не придуманными цифрами**: «Дальше веду по датчикам телефона
  и твоей скорости. Если собьюсь — спрошу, что видишь».
- «Твоя средняя скорость 30–60 км/ч» можно сказать **только если** это измерено (последние GPS,
  интеграл акселерометра) или сказано водителем. Выдумывать скорость запрещено.

**Реплика 4.** Водитель: «Супер, еду».
- Ответ короткий или молчание. Дальше обычные подсказки. Метры звучат только при `guidance=exact`,
  «примерно» при `approximate`.
- Движок продолжает считать. При σ > 150 м и наличии ориентиров впереди штурман **сам** в
  безопасный момент спрашивает: «Видишь впереди справа АЗС WOG?» (проактивность B7, с антиспамом).

**Реплика 5.** Водитель: «Что-то сбился опять, куда дальше?»
- Внутри: σ снова велика. Штурман не выдаёт уверенный манёвр и спрашивает: «Скажи, что видишь?»

**Реплика 6.** Водитель: «Вижу станцию метро, хз какая, а напротив магазин Дніпро-М».
- Внутри: `locate_by_description` с объектами `[{metro_station}, {shop, name_variants:["Дніпро-М",
  "Днипро М","Dnipro-M"], relation:"opposite", of:0}]`.
- Код ищет **пары** «вход или станция метро + Дніпро-М в пределах ~80 м через дорогу» в области
  неопределённости и по маршруту.
- «Хз какая» — это нормально: имя станции не требуется, пару делает уникальной сочетание
  объектов.
- Если пара единственная: `confirm_position` → `get_guidance_from_here` → ответ «Понял, ты у метро
  Васильківська. Прямо примерно 200 м, на светофоре налево — и сразу остановка, это место
  прибытия». Каждая часть фразы должна подтверждаться данными: светофор = `highway=traffic_signals`
  на узле манёвра, остановка = `highway=bus_stop` / `public_transport=platform` у точки назначения.
- Название из данных может отличаться от сказанного («Васильевская» → «Васильківська»). Штурман
  называет, как в данных, но понимает любой вариант.
- Если пар несколько: различающий вопрос. Если ни одной: честно сказать и попросить другой ориентир.

**Главный принцип сценария:** штурман **спрашивает → проверяет по карте → убеждается в
уникальности → переставляет позицию через движок → ведёт от ориентиров → честно говорит о
точности**. Любой шаг без данных заменяется вопросом, а не догадкой.

### 5.5 Что решает LLM и что гарантирует код

| Решение | Кто |
|---|---|
| Понять, что «пропал навигатор» = нужна локализация | LLM |
| Превратить «Фора, за ней перекрёсток» в структурированное описание объектов и связей | LLM |
| Найти объекты в данных, проверить связи, посчитать уникальность и различающие признаки | **код** (`locate_by_description`) |
| Решить: переставить позицию или переспросить | LLM, по результату инструмента; код отклоняет `confirm_position` для неуникального кандидата без явного подтверждения водителя |
| Новая позиция и её σ | **движок** |
| Манёвр, расстояние, ориентиры у манёвра | **код** (`get_guidance_from_here`) |
| Формулировка короткой фразы | LLM |
| Разрешено ли называть метры | **код**: поле `guidance` / `distance_withheld` |

### 5.6 Жёсткие запреты для штурмана (проверяются тестами и грейдером)

1. Не называть место, улицу, станцию или бренд, которых нет в результатах инструментов.
2. Не давать «через N м», когда `guidance ≠ exact`, и не давать манёвр при `guidance = none` без
   локализации.
3. Не переставлять позицию по неуникальному совпадению без подтверждения водителя.
4. Не выдумывать скорость, время, рейтинги, цены, часы работы.
5. Не говорить, что маршрут безопасен во время тревоги.
6. Не говорить «вас глушат/спуфят» как факт; говорить «GPS выглядит ненадёжным».
7. Не задавать больше одного вопроса за раз в движении и не говорить за 20 с до манёвра.
8. Не молчать при ошибке: честно сказать, что недоступно и что можно сделать.

### 5.7 Неоднозначность: 0 / 1 / много совпадений

| Совпадений | Поведение |
|---|---|
| 0 | «Не нахожу X рядом» + просьба о другом ориентире (название улицы, остановка, АЗС, крупная вывеска). Позиция не меняется. |
| 1, на маршруте или рядом | Переставить позицию, вести дальше. |
| 1, но далеко от оценки (> 3σ) | Переспросить («Ты точно на Х? Это в 2 км от того, где я тебя считаю») — защита от ошибки распознавания. |
| ≥ 2 | Один различающий вопрос. Вопрос выбирает **код**: признак, который лучше всего делит кандидатов (сторона дороги, соседний объект, тип перекрёстка). LLM только формулирует. |

### 5.8 Как закрыть «миллионы сценариев»

Не писать сценарии. Вместо этого:
1. **Общие инструменты**, которые принимают *любую* комбинацию объектов карты и связей
   («рядом», «напротив», «за ним», «на перекрёстке», «слева/справа»).
2. **Плотные реальные данные** OSM вокруг маршрута: магазины любых брендов, метро, остановки,
   светофоры, знаки, АЗС, банки, аптеки, церкви, мосты, названия улиц.
3. **Генератор тестов** (раздел 7.2): берёт случайную точку на случайном маршруте из реальных
   данных, строит описание «что видит водитель» из настоящих соседних объектов, с шумом (опечатки,
   «хз какая», неполные названия, рус/укр). Затем проверяет, что система локализует правильно или
   честно переспрашивает. Так проверяются десятки тысяч вариантов без единого написанного руками.
4. **Holdout-набор диалогов**, который никогда не используется при настройке промпта: доказательство,
   что штурман обобщает, а не заучивает.

## 6. Что нужно построить (бэклог с техзаданием)

Порядок — по приоритету. Каждый пункт закрывается только доказательствами из раздела 7.

### B0. Подключить живой мозг (блокер №1)
- Ключ LLM только в env бэкенда (или в настройках облачной среды); запуск `npm run ai:backend`.
- Живой eval: `npm run eval:ai -- --suite all`. В отчёт идут pass rate по наборам, стоимость и
  латентность, `cache_read_input_tokens`.
- Приложение: `EXPO_PUBLIC_NAVIA_AI_BACKEND_URL` (https), согласие включено.
- **Готово, когда:** живой eval выполнен и отчёт закоммичен; в приложении ответ приходит из LLM
  (в логе провайдер и модель), а не из запасного режима.

### B1. Данные карты для ориентиров
- Расширить `OSM_CATEGORY_SELECTORS` и `LandmarkCategory`: `metro_station`
  (`railway=station`+`station=subway`, `railway=subway_entrance`), `bus_stop`
  (`highway=bus_stop`, `public_transport=platform`), `traffic_signals`, `traffic_sign`
  (`traffic_sign=*`, `maxspeed` на узлах), `shop_any` (любой `shop=*` с `name` или `brand`), `bank`,
  `place_of_worship`, `bridge`.
- Поиск по имени и бренду с вариантами рус/укр/лат (уже есть `name_variants`). Добавить
  транслитерацию и нечёткое сравнение: «Днипро М» ≈ «Дніпро-М», «Васильевская» ≈ «Васильківська».
- Офлайн-индекс POI Киева (`scripts/data`) с этими категориями.
- **Готово, когда:** тест на **записанном реальном** Overpass-ответе (файл-фикстура с датой и
  запросом, не выдуманный) находит станцию метро, Дніпро-М, светофоры и остановки.

### B2. Дорожный граф вокруг машины (не только линия маршрута)
- Передавать `networkForRoute` в `NavigationEngine` в приложении: граф из OSM-экстракта
  (офлайн-пакет) или из Overpass `way[highway]` в коридоре маршрута ± 1–2 км.
- **Готово, когда:** в `closed-loop` с графом города съезд с маршрута без GPS распознаётся;
  отчёт MC до и после.

### B3. Движок: принять внешнее наблюдение позиции
- `NavigationEngine.applyExternalObservation({ location, radiusM, headingHintDeg?, source:
  "driver_landmark" })` → `ResilientNavigator.relocalizeAt(...)`: пересев частиц в радиусе
  по графу с учётом направления маршрута.
- `positioning.source = "LANDMARK"`, `LocationState` → RECOVERED или REDUCED по σ.
  `secondsSinceTrustedFix` не сбрасывать как для GPS; хранить `lastLandmarkFixAgeS`.
- Надёжный GPS после этого по-прежнему побеждает; ложный GPS не должен «перетянуть» назад.
- **Готово, когда:** unit-тесты для потери, наблюдения у ориентира, σ ≤ 60 м и правильного
  ребра графа; тест «наблюдение + потом подменённый GPS» проходит; MC-тип
  `driver_landmark_help` повышает доезд.

### B4. Инструмент `locate_by_description` (read)
- Вход: `objects: [{ category?, name_variants?, side?: "left"|"right"|"ahead"|"behind",
  relation?: "near"|"opposite"|"after"|"before"|"at_junction", of?: index }]`,
  `driver_heading_hint?`.
- Область поиска: круг вокруг оценки движка радиусом `clamp(3σ, 300 м, 3 км)` плюс коридор маршрута.
- Выход (без координат): `candidates: [{ id: "l1", summary, score, on_route, distance_from_estimate_m,
  matched_objects }]`, `unique: bool`, `discriminating_question_hint` (признак, лучше всего
  разделяющий кандидатов), `searched_radius_m`, `data_source`.
- **Готово, когда:** тесты для 0 / 1 / 2+ совпадений, связей «напротив» и «за ним», нечёткого имени;
  генератор (7.2) показывает ≥ 95 % правильной уникальной локализации при уникальном описании и
  ≤ 1 % уверенно ложной.

### B5. Инструмент `confirm_position` (safe_action, с отменой)
- Вход: `candidate_id`, `driver_confirmed?`. Код отклоняет неуникального кандидата без
  подтверждения водителя.
- Вызывает B3. Действие логируется и отменяется («нет, я не там» → вернуть прежнее облако).
- **Готово, когда:** тесты политики (отказ без подтверждения, отмена, двойное подтверждение).

### B6. Инструмент `get_guidance_from_here` (read)
- Следующие 1–3 манёвра **относительно ориентиров**: «на N-м перекрёстке», «после светофора»,
  «за АЗС справа», сторона дороги, `distance_m` или `distance_withheld: "uncertain"`.
- Ориентиры на манёвре — из B1 (светофоры, знаки, POI).
- Финал маршрута (C12): что рядом с точкой прибытия (остановка, вход, сторона дороги).
- **Готово, когда:** на реальной фикстуре инструмент выдаёт только объекты из данных и тест
  проверяет каждое имя.

### B7. Проактивный запрос ориентира
- Событие `position_uncertain_landmark_available`: σ > 150 м, скоро манёвр, впереди есть хорошо
  видимый ориентир.
- Штурман спрашивает «видишь ли X?». Ответ «да» или «нет» — это наблюдение для B5.
- Антиспам как у `ProactiveEngine`, не ближе 20 с до манёвра.
- **Готово, когда:** тесты антиспама; MC-прогон с «водителем, отвечающим на вопросы» (с
  вероятностью ошибки) показывает рост доезда.

### B8. Инструмент `report_driver_observation` (safe_action)
- «Стою в пробке», «повернул направо», «еду около 40», «я на мосту».
- Код превращает это в ограничение для фильтра: стоянка, поворот, скорость как слабое наблюдение.
- **Готово, когда:** тесты: «повернул направо» при двух кандидатах-рёбрах убирает неверное.

### B9. Сборка на iPhone и реальная поездка (делает локальная сессия на Mac)
- Иконки, `npx expo prebuild`, `npx expo run:ios --device --configuration Release`
  (`docs/HANDOFF_IOS.md`).
- Поездка по протоколу из 7.5, с логом телеметрии.

### B10. Остальное (после B0–B9)
Фоновый режим (`UIBackgroundModes: location, audio`); реальный источник тревог; офлайн-тайлы и
маршрутизация; сохранённые места в хранилище; CI (GitHub Actions: test, typecheck, mobile tsc);
Sentry; privacy manifest; фид пробок; укрепление бэкенда (rate limit, auth, логирование без
персональных данных); усиление против подмены с медленным дрейфом (77,1 %).

## 7. Приёмка: как доказывается каждый шаг

### 7.1 Юнит-тесты (детерминированно, без ключа)
- Каждый новый инструмент: успех, пустой результат, ошибка источника, неуникальность, политика.
- Движок: наблюдение у ориентира, σ, конфликт с GPS, отмена.
- **Фикстуры данных — только записанные реальные ответы** (Overpass или экстракт OSM) с датой,
  запросом и лицензией ODbL в заголовке. Выдуманные POI в тестах локализации запрещены. В тестах
  синтетического мира они допустимы и помечаются как синтетические.

### 7.2 Генератор сценариев «потерялся → описал → локализован» (≥ 10 000 вариантов)
- `packages/core/sim/landmark-relocalization.ts`: случайный маршрут, случайная точка потери GPS,
  случайная ошибка оценки (100–1500 м), описание из 1–3 **реальных** соседних объектов с шумом
  (опечатки, «хз какая», частичные имена, рус/укр, неверная сторона с вероятностью 10 %).
- Метрики:
  - правильная локализация при уникальном описании ≥ 95 %;
  - уверенно ложная ≤ 1 %;
  - при неоднозначности задан вопрос в 100 % случаев;
  - медиана ошибки после локализации ≤ 40 м.
- Отчёт: `packages/core/sim/reports/landmark-10k.json` + краткая таблица в `docs/GNSS_DENIED_REPORT.md`.

### 7.3 Замкнутый цикл 100k с помощью водителя
- Добавить в `closed-loop.ts` модель водителя, который отвечает на вопросы штурмана об ориентирах
  (с ошибками).
- Сравнить доезд и «уверенно не там» с текущими 90,5 % и 5,1 %. Ухудшение любого типа помех
  больше чем на 1 п.п. = регрессия, блокирует мерж.

### 7.4 Диалоговый eval
- Новая категория `gps_loss_dialog`: ≥ 60 кейсов в dev + ≥ 30 в holdout, рус и укр, опечатки,
  суржик, «хз», многоходовые (как эталон 5.4).
- Проверки грейдера:
  - вызван `locate_by_description` до называния места;
  - нет метров при `guidance ≠ exact`;
  - при неуникальности есть вопрос и нет `confirm_position`;
  - все имена в ответе есть в результатах инструментов;
  - язык ответа совпадает;
  - ≤ 2 предложений в движении.
- Holdout **не использовать** для правки промпта. Правка промпта под конкретный holdout-кейс = нарушение.
- Живой прогон (B0): pass rate dev и holdout, стоимость за 100 диалогов, p50/p95 латентности.

### 7.5 Реальная поездка (только владелец или локальная сессия, в облаке невозможно)
- Маршрут по Киеву 15–25 км: тоннель или путепровод, подземный паркинг, участок с отключённым
  GPS (авиарежим с отключённым только GPS — через системные настройки геолокации),
  2 локализации голосом по ориентирам.
- Лог: `telemetry-logger` → файл. Метрики: ошибка позиции против трека телефона после
  восстановления, число неверных подсказок, реакция на слова водителя.

### 7.6 Регрессия всегда
`npm test` · `npm run typecheck` · `(cd apps/mobile && npx tsc --noEmit)` · `npm run eval:replay` ·
`npm run sim:gnss` (2k — быстрый контроль, отчёт сравнивается с предыдущим).

## 8. Протокол работы Claude Code (обязателен)

Цель протокола: **каждый день — измеримый шаг вперёд, без многодневного кручения на месте.**

### 8.1 Одна задача — один пункт бэклога
1. Взять **один** пункт из раздела 6 (по порядку, если владелец не сказал иначе).
2. Прочитать нужные файлы (не весь репозиторий).
3. Записать в чат **критерий готовности** из раздела 6/7 для этого пункта.
4. **Сначала написать падающий тест**, запустить и показать, что он падает, и почему.
5. Реализовать минимально, чтобы тест прошёл, без побочных «улучшений».
6. Запустить регрессию 7.6. **Всё красное чинится немедленно**, до любых следующих шагов.
7. Коммит с понятным сообщением: что, зачем, чем доказано. Один пункт — один или несколько
   небольших коммитов. Push в рабочую ветку.
8. Отчёт владельцу по форме 8.3.

### 8.2 Правила
- **Не выдавать желаемое за сделанное.** «Сделано» = есть тест и его вывод. «Не проверено» пишется
  словами «не проверено».
- **Не имитировать.** Нет ключа, данных или устройства → остановиться и написать, что нужно от
  владельца (раздел 9). Не подставлять фейковые данные и не называть демо реальным.
- **Никаких if по фразам водителя** в основном пути. Понимание языка — только LLM. Запасной
  детерминированный режим не расширяется, кроме исправления ошибок.
- **Никаких ключей в коде, в Git и в `EXPO_PUBLIC_*`.** Не просить владельца вставить ключ в чат.
- **Не утверждать, что приложение установлено на iPhone,** если это не сделано и не проверено на
  устройстве.
- **Не ломать архитектуру раздела 3.** LLM не считает позицию; движок не разговаривает.
- **Не мержить PR сам.** Мерж делает владелец.
- **Лимит времени:** если пункт не сходится за 2 попытки подряд, остановиться, описать гипотезы
  и факты (вывод тестов), предложить решение, спросить владельца. Не крутить часами.
- **Числа только из прогонов.** Любая цифра в отчёте (%, м, $) должна иметь команду, которой
  она получена.

### 8.3 Формат отчёта после каждого пункта
```
ПУНКТ: B4 locate_by_description
БЫЛО: <одна строка, с цифрой если есть>

ФАЙЛЫ: <список>
ДОКАЗАТЕЛЬСТВО: <команды + ключевые строки вывода: N/N tests, метрики>
```

## Приложение B. Словарь
- **σ (сигма)** — радиус неопределённости позиции в метрах, который считает движок.
- **DR (dead reckoning)** — счисление пути по датчикам без GPS.
- **Фильтр частиц** — множество гипотез «где машина» на графе дорог, взвешиваемых по датчикам.
- **Локализация по ориентиру** — перестановка позиции движка в точку, которую водитель подтвердил,
  описав, что видит.
- **Holdout** — набор тестовых диалогов, который не используется при настройке, чтобы проверить
  обобщение.
- **Запасной режим** — детерминированные ответы без LLM; работает без сети и ключа, но «не думает».
